# 贾静文_C6A_demo｜仪表盘演示与验证证据

本目录是 C6A 仪表盘的**真实运行证据**，不是设计稿。每一张截图都是 `file://` 直接打开本地页面后由 Edge 无头模式渲染出来的实际像素。

## 怎么自己跑一遍

仪表盘零依赖、不需要服务器、不需要联网：

```
双击 贾静文_C6A_仪表盘\index.html
```

或者直接带视图锚点打开某个页面：

```
index.html#view=overview    总览
index.html#view=challenges  挑战清单
index.html#view=coverage    交付物校验
index.html#view=timeline    时间线
index.html#view=dict        口径与说明
```

## 截图清单

| 文件 | 对应视图 | 说明 |

## 怎么验证截图不是同一张图

早期版本五张截图的字节数完全一样（都是 88873），原因是哈希路由没有在初始化时生效，无论访问哪个锚点都渲染总览页。修复后逐张比对 SHA-256：

| 文件 | 字节数 | SHA-256 前 12 位 |
|------|--------|------------------|
| `01_总览.png` | 97176 | `FE657EF19E42` |
| `02_挑战清单.png` | 141308 | `7F28B468F642` |
| `03_交付物校验.png` | 114112 | `7C7BAC3F7D3A` |
| `04_时间线.png` | 127186 | `3EE869DA515B` |
| `05_口径与说明.png` | 109046 | `90721E77CDA2` |

> 以上为最终版实测值。口径说明页补充 T0 排除实算后曾整批重拍，截图与当前 `index.html` 一致。

互不相同（5/5 distinct），说明五个视图确实各自独立渲染。

## 除了截图还做了什么校验

截图只能证明"渲染出来了"，不能证明"内容对"。所以额外做了 DOM 转储核对（`dom_check.html` 为其中一次转储）：

- `class="kpi"` 命中 **7** 次 → KPI 卡片按预期渲染
- `data-code="C` 命中 **20** 次 → 20 个挑战全部进入 DOM，没有漏行
- 页面主体存在，未落到兜底的"数据加载失败"分支

这一步曾抓到一个真实问题：截图看起来正常，但 DOM 里挑战行数量不对，说明是渲染逻辑问题而不是样式问题。

## 与数据的对应关系

仪表盘不内嵌任何硬编码数字，全部来自 `贾静文_C6A_data\dataset.json`，由 `build_dataset.py` 从平台 API 实时生成。因此：

- 平台数据变了 → 重跑 `build_dataset.py` → 刷新页面即可，无需改前端代码。
- 截图与 Excel 总表来自**同一份** dataset.json，两者数字必然一致。
