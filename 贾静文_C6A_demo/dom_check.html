数据字典与口径

数据来源与权威性
① 平台 list-challenges：挑战定义与 required_deliverables，权威； ② 平台 list-my-submissions：提交记录与状态，权威； ③ 本地扫描脚本：仅用于校验「本机是否留有符合命名的交付物文件」，属于辅助证据，不能推翻平台状态。 三者冲突时以平台 API 为准，并在缺失项表中标注。
challenge.code
从挑战标题用正则 C\d{1,2}[A-Z]? 提取的代号，仅用于展示与分组，不参与业务判断。
submission.status
平台提交状态。checked = 已审核并进入待教师评审；needs_revision = 需按意见返工，不会自动转通过。
submission.task_state
平台评估任务状态，可能为空。为空不等于失败，只表示平台未回填。
local_check.status
complete = 全部要求项命中；partial = 部分命中；empty = 有文件但零命中；not_scanned = 本机无该挑战目录。
覆盖率 coverage_pct
公式：已提交挑战数 ÷ 已发布且可识别代号的挑战数 × 100%。分母排除测试类挑战（如 T0）。
已知局限
1) 平台仅提供本人提交记录，无法统计同班其他学生，故本仪表盘是「个人视角」，不是班级口径； 2) 本地扫描依赖命名约定，改名会导致误判为缺失； 3) 时区为 UTC，与北京时间相差 8 小时，跨日统计需注意。
